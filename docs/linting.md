# Linting & Formatting

This repo enforces style with two linters — [ruff](https://docs.astral.sh/ruff/)
for Python and [clang-format](https://clang.llvm.org/docs/ClangFormat.html) /
[clang-tidy](https://clang.llvm.org/extra/clang-tidy/) for C/C++ — plus a few
generic hygiene checks. All of it runs two places:

- **Locally**, via [pre-commit](https://pre-commit.com), on every `git commit`
  (once you've run `pre-commit install` — see [CONTRIBUTING.md](../CONTRIBUTING.md)).
- **In CI**, on every push/PR, via [lint.yml](../.github/workflows/lint.yml)
  (Python + hygiene) and [cpp-linter.yml](../.github/workflows/cpp-linter.yml)
  (C/C++).

Both run from the same config files at the repo root
([pyproject.toml](../pyproject.toml), [.clang-format](../.clang-format),
[.clang-tidy](../.clang-tidy)), so a clean local `pre-commit run` means CI
will be clean too.

## Python — ruff

Config: [pyproject.toml](../pyproject.toml), `[tool.ruff]`.

**Formatting rules (mandatory, auto-fixable):**

| Rule | Value |
|---|---|
| Line length | 100 |
| Indent | 4 spaces |
| Quotes | double (`"..."`) |
| Trailing commas | magic trailing comma respected (a trailing comma in a collection forces one-item-per-line) |
| Target Python version | 3.11 |

**Lint rules checked (not just formatting):** `E` (pycodestyle), `F`
(pyflakes — unused imports/vars, undefined names, etc.), `I` (isort — import
sorting/grouping). Unused variables are allowed if underscore-prefixed
(`_unused`, `_`).

### Running it locally

```sh
ruff format .          # rewrite files to match formatting rules
ruff check .           # report lint issues
ruff check --fix .     # report + auto-fix what's fixable
```

`pre-commit run --files <path>` runs the same two steps (`ruff --fix` then
`ruff-format`) scoped to given files; `pre-commit run --all-files` runs them
repo-wide.

### Exempting code from ruff

- **One line:** append `# noqa` (suppresses everything on that line) or
  `# noqa: E501` (suppresses only that rule — prefer the specific form so you
  don't accidentally hide a real bug later).

  ```python
  import unused_but_needed_for_side_effects  # noqa: F401
  ```

- **A whole file:** put `# ruff: noqa` on its own line anywhere in the file
  (conventionally near the top).

- **A rule, repo-wide, for a path pattern:** add a
  `[tool.ruff.lint.per-file-ignores]` table in `pyproject.toml`, e.g.:

  ```toml
  [tool.ruff.lint.per-file-ignores]
  "**/tests/*" = ["E501"]
  ```

  Prefer this over scattering `# noqa` when an entire directory (generated
  code, vendored scripts) needs the same exemption.

- **A rule, repo-wide, everywhere:** add it to `ignore = [...]` under
  `[tool.ruff.lint]`. This affects every contributor — only do this with team
  agreement, and leave a comment saying why.

## C/C++ — clang-format (style) and clang-tidy (static analysis)

Config: [.clang-format](../.clang-format), [.clang-tidy](../.clang-tidy).
Applies to the STM32 firmware under `High_Voltage/`. Generated/vendored code
(`Drivers/`, `build/`, `Debug/`, `cmake/stm32cubemx/`, and `.ld`/`.ioc`/`.s`/`.S`
files) is excluded everywhere via the `exclude:` pattern in
[.pre-commit-config.yaml](../.pre-commit-config.yaml) — it's generated by
CubeMX/ST, not ours to reformat.

### clang-format (formatting, mandatory)

Based on the Google style, with two overrides:

| Rule | Value |
|---|---|
| Column limit | 100 |
| Indent width | 4 |

### Running it locally

```sh
clang-format -i path/to/file.c              # rewrite in place
clang-format --dry-run --Werror path/to/file.c   # check only, non-zero exit if it would change
```

Or via pre-commit, which runs it with `--style=file` (i.e. use the repo-root
`.clang-format`):

```sh
pre-commit run clang-format --files path/to/file.c
```

### Exempting code from clang-format

Wrap the region you don't want reformatted:

```c
// clang-format off
static const uint8_t lookup_table[16] = {
    0x00, 0x11, 0x22, 0x33,
    0x44, 0x55, 0x66, 0x77,
};
// clang-format on
```

There's no single-line form — `off`/`on` always bracket a region (even a
one-liner). Use sparingly; it's meant for things like hand-aligned tables
where the formatter's default would hurt readability, not as a way to dodge
style review.

### clang-tidy (static analysis)

Enabled check families (from `.clang-tidy`): `boost-*`, `bugprone-*`,
`performance-*`, `readability-*`, `portability-*`, `modernize-*`,
`clang-analyzer-*`, `cppcoreguidelines-*`. `WarningsAsErrors` is empty, so
findings are warnings, not hard failures, but CI still surfaces them (see
[cpp-linter.yml](../.github/workflows/cpp-linter.yml) — "Fail on lint errors"
fails the job if the linter action reports checks-failed).

clang-tidy needs a CMake compile database (`compile_commands.json`) to
resolve includes (STM32 HAL/CMSIS headers, etc.) — without one it produces
bogus "file not found" errors instead of real findings. That's why it's
`stages: [manual]` in `.pre-commit-config.yaml` (skipped on a normal
`git commit`) and only runs automatically in CI, where the project is
configured first.

To run it locally:

```sh
cd High_Voltage/Tractive_Battery      # or the Charging_Cart UI project
cmake --preset Debug                  # generates build/Debug/compile_commands.json
pre-commit run --hook-stage manual clang-tidy
```

or invoke it directly against one file:

```sh
clang-tidy -p High_Voltage/Tractive_Battery/build/Debug path/to/file.c
```

### Exempting code from clang-tidy

- **One line:**

  ```c
  int x = risky_conversion();  // NOLINT
  int y = risky_conversion();  // NOLINT(bugprone-narrowing-conversions)
  ```

  Always prefer naming the specific check (as reported in the diagnostic,
  e.g. `bugprone-narrowing-conversions`) over a bare `NOLINT`, so an
  unrelated new finding on that line doesn't get silently swallowed.

- **The next line** (useful when the flagged construct is generated or you
  can't put a trailing comment on it):

  ```c
  // NOLINTNEXTLINE(readability-magic-numbers)
  configure_timer(84);
  ```

- **A block:**

  ```c
  // NOLINTBEGIN(cppcoreguidelines-avoid-magic-numbers)
  ... several lines of register init with literal constants ...
  // NOLINTEND(cppcoreguidelines-avoid-magic-numbers)
  ```

- **A whole file, or repo-wide:** don't use inline suppressions for this —
  edit `.clang-tidy` instead. Either add the file/directory to a
  `HeaderFilterRegex`/exclude pattern, or (for a check that's genuinely wrong
  for this codebase) remove it from `Checks:`. Both affect every
  contributor, so raise it with the team first.

## Generic hygiene hooks

Also run on every commit/CI pass (from
[.pre-commit-config.yaml](../.pre-commit-config.yaml), not project-specific
config):

- `check-yaml` — YAML files must parse.
- `end-of-file-fixer` — files must end with exactly one newline.
- `trailing-whitespace` — no trailing whitespace on any line.

These follow the same vendor-code exclusion as the language linters. If a
generated file needs to be exempt from these (rare — the existing exclude
pattern already covers `Drivers/`, `build/`, `Debug/`, `cmake/stm32cubemx/`),
extend the top-level `exclude:` regex in `.pre-commit-config.yaml` rather
than fighting it file-by-file.

## Checking what CI will check, before you push

CI only lints files that changed relative to the PR/push base (see the
"Resolve diff base" step in `lint.yml`), not the whole tree — so match that
locally instead of `--all-files`, which will also flag pre-existing issues
elsewhere in the repo:

```sh
pre-commit run --from-ref main --to-ref HEAD
```
